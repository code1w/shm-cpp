# RingBuffer 证明审查与独立约束验证

本轮审查上一轮模型假设，补充任意逻辑轮次的算术不变量，并独立编码最关键的丢唤醒坏状态。生产实现没有修改。此文是可检查的证明草案，仍不是全部实现的机器验证精化证明或独立专家审查。

## 审查发现与补强

上一轮 `reader_rearm.c` 有两项范围限制：

1. 第一次模拟等待通过 `assume(events > 0)` 只保留已完成等待的路径。因此，该模型最终断言不能单独排除第一次等待永久阻塞；上一轮单轮等待模型另行检查了这一坏状态。
2. 它把已发布字节全部当作可消费数据，使用排空后的观测值重新武装。生产 `ShmConnection::DrainRing` 则在 DrainRingOnce 前获取 WritePos 基线；codec 可能保留不完整帧，环非空也可以合法等待。

这两项不意味着此前通过结果无效，但意味着不能把该模型解释为真实应用层全部等待路径的证明。

新增 `reader_rearm_audit.c` 按实际“读取前取基线 → 尝试消费 → Arm”顺序建模；保留尚未完成的首次等待状态，不使用 assume。原子计数为 0 时模拟线程仍睡眠，随后写方可以继续完成发布；主线程只在写方结束后检查是否仍缺少通知。对完整帧才要求重新处理；半帧留在环中允许睡眠。

| 新模型 | 结果 | 完整事件图 |
|---|---|---:|
| 单字节为完整单元 | 通过，无 assume 排除路径 | 255 |
| 两字节组成完整帧 | 通过，无 assume 排除路径 | 255 |
| 只发布一个字节的半帧 | 通过，合法等待 | 21 |
| 删除读方栅栏 | 检出安全违反 | 首个反例前 8 |
| 删除写方栅栏 | 检出安全违反 | 首个反例前 8 |

模型仍只有两次发布、两轮尝试，不模拟真正 codec、poll 或退出。保留阻塞状态是有限安全检查，不等于证明线程总能被调度。负对照中工具提前报错时的 blocked 输出不代表使用了 assume。

## 任意轮次的逻辑游标不变量

引入无界的逻辑整数：R 为消费位置，W 为已发布位置，L 为写方本地位置，S 为读位置快照，C 为容量。要求：

`0 <= S <= R <= W <= L`，且 `L - S <= C`。

由此可得已发布和本地占用均不超过容量：`W-R <= L-R <= L-S <= C`。初态 R=W=L=S=0 满足不变量。

`ring_invariant_smt.py` 使用 Z3 对所有满足前提的整数状态证明以下七项转换保持相应不变量，而非枚举固定次数：

| 转换 | 前提 / 状态变化 |
|---|---|
| 未发布写入 | 0<n<=C-(L-S)，令 L'=L+n |
| 发布 | W'=L |
| 消费 | 0<=n<=W-R，令 R'=R+n |
| 取消 | L'=W |
| 回滚 | 0<=p<=L-W，令 L'=W+p |
| 更新快照 | S<=S'<=R |
| 普通写入 | L=W，0<n<=C-(W-S)，发布 W'=W+n |

七个“前提成立但后置性质不成立”的查询全部 UNSAT；每个转换的前提另查 SAT，避免不可能前提导致空洞通过。故意只检查 n<=C、不检查剩余空间的负对照找到 SAT 的超额写入反例。初态也单独检查。

这给出了算术层的归纳结构：基例成立，每个允许转换保持不变量，因此任意有限转换序列保持性质。它没有证明真实 C++ acquire 返回的值一定可以精化到所假设的单调逻辑 S，也没有检查 memcpy 内容。

真实游标只保存逻辑位置模 2^64 的值。需要另外论证原子修改顺序/读取一致性保证快照不倒退，容量约束限制未消费距离，才能把无界论证映射回有限整数；不能直接把 Z3 Int 换成 uint64 而沿用结论。Capacity 为 2 的幂并整除 2^64，物理索引在数值回绕时保持一致；这一算术性质及实际回绕案例由上一轮证据支持。

## 数据发布与复用的归纳义务

每个字节实例按以下生命周期论证：

- 写方写数据，随后 release 发布 W；读方 acquire 观察覆盖该字节的发布，才能读它。
- 消费者的全部数据访问发生在发布 R 的 release 之前；写方必须 acquire 到覆盖该字节的回收位置，才可复用物理槽。
- BatchWriter 只占用 S 到 L 的保守容量；Flush 前新字节不处于已发布范围。Cancel/Rewind 不能撤销已经发布的 W。
- Peek 返回的借用指针只能在对应消费提交之前使用；codec 和业务不能在提交后继续访问旧环数据。

这些边的 release/acquire 内容以及复用反例已经由 GenMC 检查。要升格为完整证明，还需把“每次读、每次写”与模型中的字节实例做机器检查的精化对应；本轮提供论证结构，未完成该精化证明。

## 等待通知的逐轮论证

正确等待条件是“没有遗漏需要继续处理的新发布”，不是“共享环必须为空”。不完整帧本身可以留在环中；当完整的新数据发布后，才需要读方重新检查。

对某一等待轮次，读方在读取前捕获基线，读取后置 Waiting，执行 SC 栅栏再检查发布位置。写方先发布，执行 SC 栅栏，再检查/抢占等待标志。核心义务是：读方未观察到新的发布时，写方不能同时遗漏这一轮等待标志。

多轮还需要以下前提和精化义务：

- 同一环只有一个写方和一个读方；同线程操作不重入，两个 Arm 不重叠。
- 写方对 Waiting 的 exchange 清零意味着承担发送通知的义务，不等于通知已经成功写入 eventfd。
- 读方撤销 Waiting 的 Awake store 发生于决定继续读取的路径；后续再进入睡眠前必须重新置 Waiting 并复查。
- 上一轮产生的多余通知可导致额外唤醒，不能作为下一轮发布必然已被消费的依据。
- 写方完成通知义务、eventfd 事件被 poll 观察、事件循环继续处理，需要独立的 syscall/平台和调度前提。若写方在发布与通知之间退出，恢复依赖 UDS EOF 路径。
- 生产 DrainRing 的基线取自处理前 WritePos，不能假设无限长处理期间游标数值绝不会绕满整圈。当前可信、受控消息量场景可以给出单次处理进展小于 2^64 的约束；该约束需保留为论证前提。

本轮对单轮的核心 SC 矛盾做独立检查，并以无 assume 模型补强两轮边界；没有自动证明任意轮次等待状态机到实际事件循环的精化与最终进展。

## 独立的 Z3 丢唤醒约束检查

Z3 4.12.2 在独立 venv 中运行，不复用 GenMC LLVM 解释器、运行时 shim 或事件图算法。我们手写最小约束编码，因此这是独立求解方式，不是外部专家独立审查，也不是完整的第二个 C++ 模型检查器。

`wait_sc_constraints.py` 只针对 Awake 初态、两个 load 都读初值的丢唤醒分支。依据公开草案 [atomics.order 的 coherence 定义](https://eel.is/c++draft/atomics.order#3) 与 [SC fence 顺序规则](https://eel.is/c++draft/atomics.order#4.4)：

- 读方复查读到旧 write_pos，其读取在 coherence 上先于新发布。读方栅栏先于复查，发布先于写方栅栏，要求 F_reader < F_writer。
- 写方读到旧 Awake，其读取在 coherence 上先于 Waiting。写方栅栏先于检查，Waiting 先于读方栅栏，要求 F_writer < F_reader。

两个要求不能同时满足。因此两侧 SC 栅栏的坏状态查询 UNSAT。任一侧不再是 SC 时，无法形成这对约束，坏状态 SAT，与 GenMC 的负对照一致。另检查三个其他 read-source 组合可满足，并删除任一 coherence 推导边确认编码能发现其缺失。

这是所列 fence/coherence 规则的局部编码。公开草案是当前修订版本；不能把它直接声称为 ISO C++17 的完整公理或 RC11 全部语义。两个 miss 分支没有读到对端 release 的值，因此 release/acquire 本身不能建立跨线程同步边。

保存的 SMT2 包含 assert_and_track 的全部假设标签，并重新加载检查结果；否则只导出条件断言会允许标签取 false，造成错误的 SAT 复现。UNSAT core 和 SAT witness 都保留。

## 判断

已有证据足以支持在明确调用契约和当前目标平台下的工程信心，本轮未发现生产实现缺陷，并修正了证明覆盖范围的表达。算术保持性有无界 SMT 证据，关键单轮丢唤醒条件有独立局部编码验证。任意执行的完整精化证明、外部专家审查和目标平台测试仍未完成，不应再把“增加模型执行数量”当作补齐这些义务。
