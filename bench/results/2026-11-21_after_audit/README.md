# 审核修复后性能对比（2026-11-21）

当前工作区 Release `-O2 -DNDEBUG`，无 sanitizer；服务器 CPU 2、客户端 CPU 4。吞吐基准每档 3 次取中位数，原始日志保留在 `raw/`。主对照为 2026-11-10_o2_after_p15，同优化级别、同吞吐脚本与核号。MB/s 沿用程序标签，实际按 1024² 字节计算。

## 主要观察

端到端单向吞吐多数档位相对历史为 -1.4% 到 +4.5%；64B 中位数下降 7.0%，但本轮 1634.8–1892.7 MB/s 的范围包含历史 1764.5 MB/s，不能仅据三次测量认定稳定退化。上层 small/batch256 从旧 deferred 的 6,039,311 降至 3,385,292 msg/s（-43.9%），small/batch1 从旧 deferred 的 95,168 降至 71,194（-25.2%），需要关注小消息路径；big4k/batch64 相对旧 immediate 为 +27.2%，huge1m/batch4 相对旧 immediate 为 -17.5%。这些是跨版本、跨通知模式的观测差异，缺少同代码路径的即时 A/B，不能归因到某一处修复。

全部 44 次程序运行退出 0：6 次端到端吞吐、6 次 echo、30 次上层回声、2 个内部 best-of-3 微基准。原始数据、环境和复跑脚本已归档。
