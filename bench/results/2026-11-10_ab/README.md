# 受控前后对比（2026-11-10，-O2，交错运行）

## 方法

历史对比受到 CPU `powersave` 频点（1.2–3.9GHz）双态波动干扰（同一版本 512B 可在 8.9–11.2 GB/s 间跳变）。本次改为受控 A/B：

- **before**：`git worktree` 检出优化前 commit `e2bd769`，独立 `-O2` 构建。
- **after**：当前 commit `a72afb7`（全部 P0/P1 优化）。
- 两者**交错运行**（before 一轮、after 一轮），减少频点漂移：
  - `bench.sh`：3 轮，取每 payload 的 3 次中位数；
  - `bench_app`：2 轮，取中位数；
- 同机、同核（server 核 2 / client 核 4）、同 payload 网格。
- 上层对比使用同一份 `bench_app.cpp`（before worktree 中仅删掉尚不存在的 `SetDeferredNotify` 调用），只测 immediate 模式。

## 3. 结论

- **上层小消息**：batch≥8 提升 12–20%，batch=1（延迟受限）持平。
- **上层 4KB**：提升 19–24%（batch256 的 before 有流控慢样本，中位数后 +54%）。
- **上层 1MB**：从“不支持”变为可用（~2.5 GB/s）。
- **低层 raw**：1KB–768KB +1.5%~+8.8%；1MB/2MB 略有回退，需后续 profile（优先排查 `kRingDataOffset=4096` 的缓存/TLB 影响，可尝试 64KB/2MB 偏移或仅对 <=768KB 启用镜像）。
- 之前“512B +27%”的历史对比主要受频点漂移影响，受控 A/B 下为 +2%。
