## 3. ping-pong RTT（第二次运行）

| payload | SHM RTT | Socket RTT | SHM/Socket |
|---|---:|---:|---:|
| 64B | 449 ns | 10.33 µs | 0.04x |
| 256B | 453 ns | 9.87 µs | 0.05x |
| 1KB | 854 ns | 10.65 µs | 0.08x |
| 4KB | 3.35 µs | 10.58 µs | 0.32x |
| 16KB | 12.1 µs | 20.7 µs | 0.59x |
| 64KB | 42.9 µs | 32.7 µs | 1.31x |
| 256KB | 166 µs | 73.1 µs | 2.27x |
| 512KB | 343 µs | 138 µs | 2.49x |

- 小包 SHM 延迟优势明显（64B 约 23x）。
- 大包 ping-pong SHM 反而更慢：该 harness 每 RTT 有 4 次用户态 memcpy，且大块数据受缓存/内存带宽影响；端到端批量吞吐（第 1 节）仍是 SHM 占优，ping-pong 大包数字波动大（历史 181–364µs），不宜作为唯一依据。

## 4. 结论

- **吞吐**：小包 SHM 领先 45–49x；1KB–16KB 5.5–19x；64KB–768KB 约 3.4–4.2x；1–2MB 约 1.6–1.7x。
- **优化收益**：受控 A/B 下 raw 路径 +2%~+9%（1KB–768KB）；上层接口 +12%~+24%（见 `../2026-11-10_ab/`）。
- **已知回退**：1MB/2MB raw 路径 −5%~−10%，建议仅对 ≤768KB 启用镜像，或调整数据区偏移后复测。
